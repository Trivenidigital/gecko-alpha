## Comparator algorithm and error semantics

Resolve repo_root and require it equals git rev-parse --show-toplevel. Capture
git rev-parse HEAD as an immutable full commit ID. Git subprocess calls are argument
arrays with shell=False, check=True and timeout30seconds. Never use a moving branch
name as the comparison revision, never interpolate filenames into a shell, and
never print bundle contents. Require tracked working-tree and index cleanliness
using Git diff exit codes before comparison; local dirty-source work must be
committed in an explicitly disposable fixture for the stale-source falsifier.

Require build_dir is an existing nonsymlink directory outside repo_root, and that
repo_root is not beneath build_dir. Traverse using lstat without following links;
reject any symlink, special file or path escaping the resolved build root. Require
at least one file and index.html. Walk files deterministically in relative POSIX
path order. The checker owns no output directory and never deletes anything.

Read committed dist entries through git ls-tree -rz <pinned_sha> --
dashboard/frontend/dist, splitting only on NUL records and the first tab. Map
exact paths to regular blob modes100644/100755 and blob IDs. Symlink entries or
nonblob modes cannot satisfy a generated-file comparison. For every freshly
emitted file, require its corresponding committed dist path exists in that map.
Compare raw generated bytes to git cat-file blob <blob_id> bytes; no newline,
whitespace, source-map, timestamp or filename normalization. Report the relative
path and missing_committed_file/byte_mismatch category. Missing Git object,
subprocess failure/timeout, malformed output, or filesystem read errors fail.

Use HTMLParser to collect script src and link href from generated index.html.
Require at least one local reference. Resolve references with urlsplit and unquote,
strip query/fragment, reject scheme/netloc, empty paths, NUL, backslash and '..'
path components, and treat leading '/' as relative to generated root. Referenced
targets must be regular files included in the walked generated set. Current Vite
index has two local references. An unexpected remote or data reference fails
explicitly; do not silently omit it from the declared self-contained build check.

The comparison set is ALL freshly emitted files, not just direct HTML references:
this includes lazy JS chunks, CSS resources and copied public files. Extra files
found only in committed dist are intentionally ignored. Their retention cannot
make an otherwise matching build fail. A missing newly emitted chunk still fails
even if it is reachable indirectly rather than from index.html. This avoids a
whole-directory equality requirement that would erase historical assets.

Recheck HEAD and tracked cleanliness after comparisons; any concurrent checkout or
tracked mutation fails verification. Success identifies the exact tested checkout
SHA and count of compared files. The comparator does not claim source provenance
on its own: the CI sequence below supplies a fresh build from that same clean
checkout. Normal Git repository trust applies; this is not a hostile Git-server
or malicious workflow sandbox.

## CI integration

Use existing action generations consistently: checkout@v4, setup-python@v5 and
setup-node@v4. The official setup-node v4 action inputs support an exact
node-version. Pin Node24.14.0, the locally observed toolchain; do not use latest,
check-latest or an unbounded major range. Python3.12 runs the comparator without
installing the application. Log Node/npm versions, actual HEAD, GITHUB_SHA and
the package-lock SHA256. The lockfile fixes Vite6.4.1; npm ci must not upgrade it.

Proposed job content, inserted without changing sibling jobs:

```yaml
  frontend-dist-parity:
    runs-on: ubuntu-latest
    timeout-minutes: 10
    permissions:
      contents: read
    steps:
      - uses: actions/checkout@v4
        with:
          persist-credentials: false
      - uses: actions/setup-python@v5
        with:
          python-version: '3.12'
      - uses: actions/setup-node@v4
        with:
          node-version: '24.14.0'
      - name: Install locked frontend dependencies
        working-directory: dashboard/frontend
        run: npm ci --ignore-scripts --no-audit --no-fund
      - name: Verify committed frontend rebuild parity
        shell: bash
        run: |
          set -euo pipefail
          git rev-parse HEAD
          test "$(git rev-parse HEAD)" = "$GITHUB_SHA"
          node --version
          npm --version
          sha256sum dashboard/frontend/package-lock.json
          build_dir=$(mktemp -d "$RUNNER_TEMP/gecko-dist-parity.XXXXXX")
          npm --prefix dashboard/frontend run build -- --outDir "$build_dir"
          python scripts/check_dist_rebuild_parity.py --repo-root . --build-dir "$build_dir"
```

The ordinary Actions pull_request checkout is the synthetic merge candidate, so
the log reports that tested SHA honestly. A push tests its commit. No ref override
to origin/master, path skip, continue-on-error or forced success is allowed.
Missing Node, install failure, build failure and compare failure all fail this
job. No automatic caching or dependency publication is needed. Each run starts
with mktemp's fresh output directory; the ephemeral runner owns later cleanup.
No rm -rf, production directory or tracked dist overwrite is involved.

npm ci --ignore-scripts avoids dependency lifecycle hooks; optional native packages
remain installed. npm run build explicitly invokes the existing build script.
Official npm documentation confirms frozen lock behavior and ignore-scripts
semantics. The exact Linux success path still needs proof during implementation.
If install requires a lifecycle adjustment, stop and review that narrow change;
do not silently switch installers or update the lock.

Sources checked2026-09-14:
https://raw.githubusercontent.com/actions/setup-node/v4/action.yml and
https://docs.npmjs.com/cli/v11/commands/npm-ci/.
This job uses no production credentials, database, API, paid vendor or deployment

## Tests that distinguish the missing behavior

Synthetic repo fixtures commit index.html plus assets and create a separate fresh
output directory. Tests use subprocess arrays and local Git author configuration.

1. Matching index/assets pass and identify HEAD/file_count; original asset-existence
   tests continue to pass without Node.
2. Same filename but different JS bytes fails byte_mismatch while every reference
   still resolves. Removing byte comparison must make this test fail.
3. Changed index bytes or missing committed emitted asset fails; an extra historical
   committed asset passes without deletion.
4. Nested emitted lazy chunk mismatch fails even when absent from HTML references.
5. Missing/empty index, invalid local reference, missing referenced file, symlink
   output and traversal fail explicitly. An untracked working-tree copy of a
   missing Git artifact cannot satisfy committed-blob comparison.
6. Dirty tracked inputs, changing HEAD and Git failure fail rather than reading a
   different revision. Read/check success leaves tracked source/assets unchanged.
7. Parse the workflow using the already-installed YAML test dependency and assert
   this job reaches comparator after build, preserves event/job wiring, pins Node,
   has no error suppression/ref override, and retains the legacy Python guard.
   Tests must target these failure risks rather than snapshot every formatting line.

After both design approvals, initial proof builds the clean pinned Linux source
twice into separate temporary directories and compares each to HEAD. This proves
reproducibility once; permanent CI performs one build per run. Then create a
disposable fixture checkout, make and commit a visible rendered-string change
