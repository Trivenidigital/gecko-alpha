## Read boundary, limits and ownership

At create_app construction, capture an absolute database filename into a local
lane_status_db_path, using the supplied/current path at that instant. The new route
never evaluates module-global _db_path during a request. Capture independently of
subsequent app construction; two-instance tests must prove this.

Use one synchronous function in lane_status.py executed with asyncio.to_thread.
It opens sqlite3.connect(Path(path).as_uri() + '?mode=ro', uri=True, timeout=0.25)
and closes the connection in a contextlib.closing/finally inside that same worker.
No connection crosses threads. This follows existing read-only URI practice but
does not reuse the lossy helper or the shared async context manager's acquisition
cancellation boundary. Cancellation of the awaiting coroutine may leave a running
read finishing briefly; the worker still owns unconditional cleanup. Cancellation
before worker start opens no connection. Do not claim cancellation interrupts an
arbitrary OS-level filesystem stall, or add a global shared connection/cache.

Set SQLITE_LIMIT_LENGTH=65536 and a progress handler checked every1000 VM operations,
returning nonzero once1s elapsed since worker start. SQLite lock wait is250ms.
Select only signal_type, enabled, typeof(enabled), suspended_at, suspended_reason,
last_calibration_at with ORDER BY signal_type LIMIT129. At most128 records accepted;
129 or a SQLite size/VM/lock failure => whole observation unavailable. The limit is
a read budget, not a production count assumption (observed9 is not hardcoded).
One SELECT provides one SQLite statement snapshot; timestamp observed_at in UTC
is taken immediately before SELECT, conservatively aging the read. No separate
per-row connection or statement can mix lane snapshots.

Require each key is nonempty TEXT of at most128 characters, no control characters,
and unique. Invalid/duplicate keys reject the entire observation rather than
silently replacing/misjoining a lane. Exact keys are preserved; no case conversion,
alias table, trimming to another key, inferred detector-to-lane mapping or sorting
of application rows. Only the status endpoint's standalone key list is ordered.

Errors return no current rows. Connection failures, missing schema, read limits,
malformed key evidence and other SQLite failures are converted to fixed public
reason codes; do not expose filesystem paths, SQL or arbitrary exception text.
Existing application errors and CancelledError are not broadly swallowed.

## Stored evidence validation and classification

Validate the actual SQLite value/type before int/bool/string or response-model
coercion. Only typeof(enabled)='integer' with exact value0 or1 is canonical.
SQLite affinity may already normalize some writes (e.g. numeric text into INTEGER);
this design reports stored evidence, not unrecoverable original input syntax.
REAL1.5 remains REAL and must yield unknown; REAL/nonfinite values, TEXT, BLOB,
NULL and integers outside0/1 must never become enabled/disabled through coercion.

Suspension timestamp: NULL means absent. A present value must be TEXT at most80
characters containing a full date and time with seconds. Accept either ISO8601
with T/space and optional fraction/offset/Z, or the existing legacy UTC timestamp
'YYYY-MM-DD HH:MM:SS[.fraction]'. Explicit offsets normalize to UTC with overflow
guard; offset-free supported timestamps mean UTC. Date-only, empty/whitespace,
invalid types, impossible dates or times later than observed_at => invalid evidence.
Do not guess locale or silently discard invalid suspension metadata.

Classification is performed server-side once:

| Stored enabled | Suspension evidence | state / reason |
|---|---|---|
| integer1 | NULL | enabled / enabled_in_store |
| integer0 | NULL | disabled / disabled_in_store |
| integer0 | valid timestamp | suspended / suspended_in_store |
| integer1 | any present timestamp | unknown / conflicting_suspension_metadata (or invalid_suspension_timestamp) |
| anything invalid | any | unknown / invalid_enabled_value |
| integer0 | invalid timestamp | unknown / invalid_suspension_timestamp |

Validate enabled first, then timestamp; deterministic reason precedence avoids
disagreement between views. last_calibration_at does not control state or freshness.
suspended_reason/last_calibration_at are descriptive evidence only; cap their safe
text presentation at1024/80 characters respectively, with an explicit truncated
flag. Nontext descriptive fields are marked invalid details without inventing text
or overriding otherwise valid enabled/suspension evidence.

Raw enabled evidence contains sqlite_type and a bounded display representation;
never feed that display representation back into classification. JSON numeric values
must be finite; nonfinite values use explicit text evidence, blobs use bounded hex,
and truncation is flagged. React renders all details as text, never HTML. Unavailable
status is distinct from a successful empty table and a valid observation with an
unknown lane. Missing key on a valid snapshot => unknown / no_store_row.

## Endpoint schema

GET /api/signal_lane_status has no query parameters and Cache-Control:no-store.
200 body (no Pydantic coercion of unvalidated raw fields):

```json
{"meta":{"ok":true,"source":"signal_params","read_only":true,
"not_execution_eligibility":true,"observed_at":"2026-09-14T02:36:26Z"},
"lanes":[{"signal_type":"example","state":"enabled","reason":"enabled_in_store",
"evidence":{"enabled":{"sqlite_type":"integer","display":"1","truncated":false},
"suspended_at":null,"suspended_reason":null,"last_calibration_at":null}}]}
```

Design implementation may represent descriptive evidence as typed objects for
invalid/truncated fields; tests must pin the final additive endpoint schema before
building the UI. Raw status information never changes existing card payloads.
503 body has meta.ok=false, the same source/read_only/not_execution_eligibility
flags, observed_at=null, a fixed reason (read_unavailable/schema_unavailable/
read_limit/invalid_keys), and lanes=[]. A successful empty table is200/oktrue;
all displayed source keys then resolve to unknown/no_store_row.

Labels mean current recorded signal_params status only. They do not claim loaded
engine settings/cache, trust-tier, source quality, live permission, executable trade
or historical entry status. A short source explanation is always visible in each
panel, with exact observed time available in details. No flag evaluation or new
execution eligibility model is introduced.

## Frontend freshness and request ownership

Each mounted Focus/Inbox view owns one controller shared by all its annotation
instances. No per-row requests, global cross-tab cache, localStorage persistence or
reuse of the Focus hour-cached payload. On mount/resume/visible-page transition,
refresh immediately. While visible and unpaused, refresh every30s. Inbox pause
also pauses status; hidden page pauses both view controllers' status polling.
Focus does not acquire a new pause UI. Clear intervals/listeners and invalidate
request ownership on dispose.

Every refresh increments a generation and aborts the previous request. A5s timer
aborts a slow request and records unavailable; it invalidates that generation even
if the fetch implementation later resolves. Abort and generation ownership are both
required. Older success/failure/finally callbacks cannot publish after a newer
generation, timeout, pause, hidden-page transition or disposal. Never merge data
from two observations. Beginning a refresh changes presentation to refreshing;
previous values may appear only as last-observed details, not current badges.

Accept a response only if HTTP200, meta flags match, observed_at parses, every lane
has valid schema/unique key and a recognized state/reason. Invalid payload => unavailable.
The server observation must not be later than receipt wall clock by more than5s;
larger future skew => unknown/clock_skew. Up to5s tolerance ages from zero, explicitly
allowing only that bounded skew. Age at receipt is max(0, receiptWall-observedAt).
Freshness thereafter is conservative: use the maximum of wall-clock age and
receipt age plus performance.now elapsed. The60s boundary is stale at age>=60s;
no backward wall-clock adjustment may extend freshness. A backward discontinuity
over5s or invalid clock value makes status unknown until a fresh consistent response.

An owned1s render tick updates age; each projection checks clocks at render time,
and visibilitychange forces reevaluation before new visible use. Paused/hidden state
immediately stops claiming current status regardless of age. Resume never rebrands
the cached value current before a successful fresh request. Status errors do not
change card data loading, dismissals or the existing refresh error surface.

## Additive presentation

LaneStatusAnnotations receives row.surfaces plus immutable controller state. For
each exact distinct represented surface, display a compact neutral text chip such
as 'narrative_prediction: enabled', 'chain_completed: suspended', or
'top_gainers_tracker: unknown'. Avoid green trade-action styling. Deduplicate only
duplicate lane names within annotation, never source rows. Empty/malformed surfaces
give one 'Lane status: unknown' annotation with missing-source details.

Render all represented lane chips with wrapping; no best-lane summary or hidden
unknown lane. Details expose source, observed time, state reason and raw relevant
evidence. Shared panel text: 'Recorded lane status; not execution eligibility.'
On stale/pause/error, primary annotation says stale/paused/unavailable and previous
values, if retained, appear only in labeled last-observed details.

- Focus: place below the existing token/source header inside todays-focus-row-body,
  above current metrics/facts. Keep original rank, action and detail control order.
- Inbox decision cards: place below trade-decision-token and before decision label;
  pass status as a separate render argument without modifying row or board builder.
- Inbox grouped table: place beneath existing Source text in Token cell; do not
  add sortable columns, change group iteration or modify action/score/risk text.

Check narrow widths with wrapped lane names and details keyboard accessibility.
Status loading must not hide/replace cards. Do not extract or alter SignalTrustTab's
existing badge classifier in this task; its different semantics are separate scope.

## Discriminating tests and verification gates

- Actual endpoint against temporary DBs: integer0/1, REAL1.5, invalid TEXT/BLOB/NULL,
  out-of-range integer, conflicting timestamp, legacy UTC timestamp, malformed and
  UTC-overflow timestamp; successful empty table and absent key. An int/bool cast
  inserted before validation must break the fractional-value test.
- Missing file/table/column,129rows, oversized values, duplicate/null keys, read lock
  and forced SQL interruption fail unavailable; connections close on each error.
  Cancellation before worker acquisition and during a barrier-controlled read must
  leave no connection after the worker completes; do not confuse cancellation of
  the awaiter with immediate thread termination. No files are created for missing DB.
- Two apps A/B with distinct fixtures constructed in sequence, then alternating
  and concurrent calls must each return their own state. Existing reader/consumer
  behavior remains unchanged; request path never calls ScoutDatabase.initialize.
- Node tests run the production pure controller/projector with fake fetch/clocks:
  late success/failure, timeout then success, unmount/pause/resume, empty table,
  malformed payload, mixed lane state, hour-cached rows, age60s, future timestamp,
  backward wall jump and sleep/visibility resume. Last-observed enabled must never
  become current through a late callback or clock rollback.
- Render fixtures contain enabled+suspended+unknown lanes and original card keys
  in identical order/counts/groups before/after status changes; original scores,
  actionability, dismissals and seen/storage remain identical. Test both Inbox card
  and grouped-table placements and Focus. Existing API/contract tests stay green.
- After design approvals: TDD then focused API/frontend/contract tests, existing
  frontend build and generated-asset/parity checks, controlled visual inspection,
  two PR reviews and exact CI. No production queries or toggles needed for tests.
